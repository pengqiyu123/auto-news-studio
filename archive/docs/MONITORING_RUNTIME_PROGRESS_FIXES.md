# Auto News Studio 监测运行态与进度条修复说明

## 目标

把首页“开始监测”这条主链收敛为真正面向人的 3 段流程：

1. 采集素材
2. 聚合热点事件
3. 判断热度与预警

同时修掉两类体验问题：

- 进度条前后跳动
- 明明 3/3 已完成，却长时间停在运行中

## 已完成的修复

### 1. 监测主链改为 3 段

正常监测不再暴露“第 4 段收尾”。

当前日志与运行阶段应表现为：

- `阶段 1/3：开始采集到期来源`
- `阶段 1/3 完成：采集 X 条素材`
- `阶段 2/3：开始聚合热点事件`
- `阶段 2/3 完成：形成 X 个热点事件`
- `阶段 3/3：开始判断热度与预警`
- `阶段 3/3 完成：生成 X 条预警，更新 X 条重点观察`

收尾现在只是内部结束动作，不再作为单独产品阶段展示。

### 2. 进度条语义改为意图驱动

首页进度条现在按运行意图显示：

- 正常监测
- 仅采集素材
- 重建事件
- 重算预警

不再把所有动作都混成“采集中”。

### 3. 前端加了 runtime 防倒退合并

之前前端有多个轮询来源：

- `dashboard`
- `runtime/status`

旧响应偶尔会覆盖新响应，导致：

- 百分比倒退
- 阶段来回跳
- 明明已进入下一段，又被刷回上一段

现在前端会按以下信息合并 runtime：

- `run_id`
- `heartbeat / started_at / finished_at`
- 当前阶段顺序
- 百分比是否回退

旧状态不会再轻易覆盖新状态。

### 4. 去掉监测主链里的 LLM 候选判断阻塞

之前在 `scoring` 阶段里还会夹带执行候选池的 LLM judgement。

这会导致：

- 主链停在 `正在判断热度与预警`
- 模型一慢就整轮卡住

现在 LLM 候选判断已从监测主链移除，情报链只保留规则驱动。

### 5. 去掉监测热路径里的 reference baseline 刷新

之前每轮监测结束前还会执行：

- `write_reference_baseline()`

这个动作会：

- 扫描参考项目
- 读本地仓库状态
- 写参考 JSON

它与情报监测无关，却可能拖住主链收尾。

现在它已从每轮监测热路径移除，仅保留在：

- 初始化
- 参考项目列表读取时

### 6. 修复 `dashboard` 轮询覆盖后台新状态

之前 `get_dashboard()` 在某些情况下会把旧 state 再写回去，和后台正在运行的轮次抢状态。

这会导致：

- 日志已经到 3/3 完成
- 运行态却还停在 `running`

现在 `dashboard` 读取不会再把浏览器刷新顺手覆盖运行态。

### 7. 修复 `start.bat / stop.bat / backend.pid`

之前 `backend.pid` 可能被写成异常内容，例如 `+`，导致：

- `stop.bat` 不能按 PID 精准停止
- 只能退回到按端口杀监听进程

现在已修复为：

- `start.bat` 记录父进程 PID
- 启动成功后显示父子链
- `stop.bat` 能识别无效 PID 文件并忽略
- 有父 PID 时优先 `taskkill /T` 杀整棵进程树

## 当前已确认的运行模型

Windows 下现在看到两个 Python 进程，通常属于正常父子结构：

- 父进程：`.venv\\Scripts\\python.exe`
- 子进程：真正监听 `127.0.0.1:8000` 的 Python

这不等于启动了两套服务。

判断是否正常的标准不是“只有一个 Python”，而是：

- 只有一个进程监听 `8000`
- `backend.pid` 为有效数字
- `stop.bat` 能把整棵树停掉

## 仍需继续观察的点

虽然主要阻塞点已经逐步移除，但仍建议继续观察以下现象是否彻底消失：

1. `阶段 3/3 完成` 后是否稳定进入 `completed`
2. 是否还会出现 `run_status = running` 但 `current_cycle = idle`
3. 是否还会出现旧轮次残留状态覆盖新轮次

## 验收建议

每次验证用以下标准：

1. 首页点击“开始监测”
2. 进度条依次经过：
   - 采集素材
   - 聚合热点事件
   - 判断热度与预警
3. 日志出现完整 3 段
4. 最终运行态返回：
   - `run_status = completed`
   - `control_state = stopped`
   - `current_cycle = idle`
5. 进度条不再倒退

## 备注

如果代码已修改但页面行为未变化，优先检查是否只是当前 `8000` 后端实例尚未重新加载代码。
