# Auto News Studio 今日短讯 MVP 方案

更新时间：2026-05-26

## 结论先行

上一版“自动化编辑部”方向对了一半：它把重点从“让 AI 写文章”转向了“系统先做编辑判断”。但它仍然太长文中心、太重、太像一次性重写写作系统。

本方案改为：

```text
短讯为主，长文为辅。
80% 日常短讯，20% 重大事件升级长文。
```

第一阶段只做一个可落地闭环：

```text
从事件池选出 Top 3-5 个值得写的事件
-> 生成 300-600 字公众号短讯
-> 展示在“今日短讯”
-> 一键同步微信草稿箱
```

不做 `EditorialPackage` 大对象，不做多角度规划，不做五类文章模板矩阵，不做复杂风格资产。

## 为什么改成短讯优先

1. 公众号日常打开率和读完率不适合把全部价值押在 3000 字长文上。
2. 当前系统最强的是发现、聚合、趋势判断，而不是稳定生成深度长文。
3. 短讯事实边界更容易守住，AI 编造空间更小。
4. 高频短讯更适合日常更新和算法推荐。
5. 长文应该是少数重大事件的升级形态，不是默认产物。

所以核心产品定位应是：

```text
今天发生了这么多事，系统用最少操作帮用户产出几条高密度、事实可靠、可进公众号草稿箱的短讯。
```

## 来自遗漏项目的修正

### TrendRadar-master

`TrendRadar` 的价值不是代码复用。本地副本主要是静态页面、配置和文档，它更像一个热点监控产品样本。

可借鉴点：

1. 兴趣筛选：用户用关键词或自然语言兴趣描述控制“看什么”。
2. 时间段策略：不同时间段可以有不同筛选方式和分析范围。
3. 展示/分析解耦：推送内容可以短，AI 分析可以基于更完整的数据。
4. 新增热点优先：突出本次新增、热度变化和跨平台重复出现的内容。

落到本项目：

第一阶段先借“Top 3-5 今日短讯”的筛选思想，不借 MCP、复杂调度、多渠道推送。

### newshub-main

`newshub` 有新闻抓取、批处理、去重、摘要、关键词、情感、向量检索和个性化 feed。

可借鉴点：

1. 批处理，避免一次性打爆模型或上游 API。
2. 标题去重，减少重复事件占用短讯名额。
3. 摘要、关键词和情感作为筛选辅助信号。
4. 相似文章检索可作为后续“相关来源补全”能力。

不借鉴点：

它在模型失败时会返回空摘要、空关键词继续存储。这个做法不符合本项目规则：真实数据不可用时要暴露失败，不能把空结果伪装成成功。

### wiseflow-master

`wiseflow` 的价值主要在自媒体运营 Agent 和发布动作边界。

可借鉴点：

1. L3 外部发布必须要用户明确指令。
2. 素材和最终稿件分目录管理。
3. 平台上传要等待 DOM 稳定，不能上传后马上操作。
4. 发布前要做平台特定检查，例如 AI 辅助声明、封面、标签。

落到本项目：

短讯 MVP 只做到微信草稿箱。正式发布仍保持用户确认，不把发布 Agent 化作为第一阶段目标。

## 现有系统已经具备的底座

不需要新建一个完整生命周期对象。当前主项目已有足够底座：

1. `IntelEvent` 已有事件分数、来源数、平台数、告警状态、是否已生成 brief。
2. `EventDeepDive` 已有来源、全文、事实、引文、时间线、worthiness、错误状态。
3. `BriefItem` 已有标题、一句话、事实、风险、来源链接、微信 Markdown、微信草稿状态。
4. 现有接口已经支持事件深挖、生成 brief、同步微信草稿。

因此第一阶段应该复用现有 `BriefItem`，不要新增 `EditorialPackage`。

## MVP 对象：DailyBriefCandidate

`DailyBriefCandidate` 是一个展示/生成用投影，不是新的持久化主表。

建议字段：

```text
id
event_id
title
one_line_why
facts[]
risk_flags[]
short_draft
source_links[]
wechat_status
```

字段映射：

```text
title -> BriefItem.title
one_line_why -> BriefItem.one_line / why_it_matters
facts[] -> BriefItem.facts
risk_flags[] -> BriefItem.risk_notes
short_draft -> BriefItem.wechat_markdown
source_links[] -> BriefItem.source_links
wechat_status -> BriefItem.stage / delivery_status
```

这已经够跑第一版。

## 短讯结构

每条短讯固定为 300-600 字，回答三个问题：

```text
发生了什么？
为什么值得看？
现在还不能下什么结论？
```

推荐结构：

```text
标题：14-25 字，包含具体信息点
一句话发生了什么：50 字以内
核心事实：100-250 字
这意味着什么：50-120 字
还不确定什么：可选，30-80 字
来源链接：1-3 个
```

短讯不做多角度规划。短讯的“角度”就是把事实说清楚，并点出读者为什么应该知道。

## 选题规则

候选来源：

1. 已有 `intel_events`
2. 已完成或部分完成的 `event_deep_dives`
3. 近 24 小时活跃事件
4. 未忽略、未同步、未重复的事件

排序信号：

1. `alert_state`：breakout / rising 优先
2. `source_count` 和 `platform_count`：多来源优先
3. `freshness_score`：新鲜事件优先
4. `audience_fit_score`：匹配用户关注方向优先
5. `worthiness.reason`：有明确价值判断优先
6. `success_count`：已有可核验正文优先

过滤规则：

1. 已忽略事件不进入今日短讯。
2. 已有同步草稿且未变化的事件不重复推荐。
3. 只有标题、没有来源链接的事件不生成短讯。
4. Deep dive 失败时允许显示候选，但必须标记“证据不足”，不能生成可同步草稿。

## 事实纪律

保留旧版 `auto-news-分发版-v2.4.1` 的事实纪律，但只用于短讯：

1. 所有数字必须来自事实、来源正文或来源标题。
2. 所有日期必须来自来源。
3. 未确认的信息必须写进“不确定项”，不能补齐。
4. 不能把推测写成确定结论。
5. 模型失败或来源不足时要暴露失败，不用空摘要、样例数据、兜底文案伪装成功。

## 第一阶段实施切片

### 后端

新增一个轻量能力：

```text
build_daily_brief_candidates(limit=5)
```

它只做三件事：

1. 从现有事件和 deep dive 中筛 Top 3-5。
2. 对可写事件生成或复用 `BriefItem`。
3. 返回 `DailyBriefCandidate` 投影。

新增接口：

```text
GET /api/admin/editorial/daily-briefs
POST /api/admin/editorial/daily-briefs/{event_id}/prepare
POST /api/admin/briefs/{brief_id}/wechat-draft
```

其中第三个接口已经存在，应复用。

### 前端

新增一个“今日短讯”区块，可以先放在总览页，不必开新复杂页面。

每张卡片显示：

```text
标题
一句话推荐理由
核心事实 2-3 条
风险标签
来源数量
状态：可生成 / 证据不足 / 已生成 / 已同步
操作：生成短讯 / 预览 / 同步草稿 / 忽略
```

长任务要给即时反馈：

```text
正在深挖来源
正在生成短讯
正在同步微信草稿箱
```

### 测试

优先测产品边界：

1. 多事件排序能选出 Top 3-5。
2. 已忽略、已同步、证据不足事件不会被当成可发短讯。
3. Deep dive 失败不会生成伪成功短讯。
4. 短讯 Markdown 包含来源链接和不确定项。
5. 同一事件重复生成时复用已有 brief，不制造重复草稿。

## 暂不做

第一阶段明确不做：

1. `EditorialPackage` 持久化模型。
2. 22 个字段的文章生命周期对象。
3. 每个选题 3 个角度。
4. 5 种文章类型模板。
5. 复杂 writer-style。
6. AI 去痕后处理。
7. 多平台分发。
8. 自动正式发布。

这些都不是没价值，而是不该挡在短讯闭环前面。

## 第二阶段：长文升级

当短讯跑通后，再做长文升级。

升级条件：

1. 多来源、多角度重大事件。
2. 需要对比分析的产品、政策或公司动作。
3. 读者确实需要一次性搞懂。
4. Deep dive 已有足够全文、事实、时间线和引文。

长文入口：

```text
短讯卡片 -> 升级长文
```

长文类型先保留 3 个：

1. 深度分析
2. 通俗科普
3. 对比评测

## 最重要的取舍

当前不是要证明系统能写一篇漂亮长文。

当前要证明的是：

```text
系统每天能不能稳定找出 3-5 个值得写的新闻点，
并把它们变成事实可靠、信息密度高、能进公众号草稿箱的短讯。
```

只要这个闭环成立，后续长文、风格、排版、多平台分发才有真实价值。
