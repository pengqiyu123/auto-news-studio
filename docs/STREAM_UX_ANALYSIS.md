# 实时流界面 UX 评审报告

> 评审日期：2026-05-28
> 方法：跨职能团队分析（产品经理 + 运营专员 + 设计专家）
> 范围：实时流（Stream）界面，含与热点簇（Events）、预警台（Alerts）的衔接关系
> 前序文档：[OVERVIEW_UX_RESEARCH.md](./OVERVIEW_UX_RESEARCH.md)（总览页改进，已完成实施）

---

## 一、三界面管线定位

数据管线：`采集 → 归一化 → 聚类 → 评分 → 预警 → 简报 → 发布`

| 界面 | 数据模型 | 管线位置 | 核心用户价值 |
|---|---|---|---|
| **实时流** | `DiscoveryItem` | 聚类之前 | 查看原始素材"进了什么"，验证采集源是否正常 |
| **热点簇** | `IntelEvent` | 聚类之后、预警之前 | 查看哪些话题在聚合增长，决定是否深挖 |
| **预警台** | `IntelAlert` | 预警触发后 | 查看需要立即关注的高优先级事件，决定行动 |

三者是**同一管线的三个切面**：原始素材 → 聚合事件 → 行动预警。越往后信息密度越高、行动性越强。

## 二、问题清单

### P0 — 必须修（阻塞其他所有优化）

#### P0-1：客户端过滤 vs 后端分页矛盾

**现象**：后端 `GET /api/admin/intel/stream` 只接受 `page` 和 `page_size` 两个参数（`routes/intel.py:74-83`）。前端 6 个过滤维度（关键词、时间、平台、来源、变化状态、热度）和 4 种排序全部作用于当前页返回的 50 条数据。

**用户影响**：
- 默认 `timeFilter = "24h"` 过滤一页 50 条，如果最新 50 条跨越不止 24h，结果不可预测
- 选"近 1 小时"时，当前页可能 0 条匹配，用户以为"没有新素材"，实际第 2 页全是
- 界面自己承认：`note="筛选和排序当前按本页数据生效，翻页后会继续加载后端真实分页结果。"`

**实质**：API 架构缺陷，不是 UI 问题。过滤和排序必须发生在数据层。

**涉及文件**：
- 后端：`backend/app/routes/intel.py`（路由）、`backend/app/store_mixins/intel_mixin.py`（数据层 `list_discovery_items`）
- 前端：`frontend/src/screens/stream/page.tsx`（过滤逻辑 103-139 行）

#### P0-2：统计行误导

**现象**：`page.tsx:230-235` 显示"当前页 50 条 / 筛后 X 条 / 总素材 Z 条"。前两个是当前页局部统计，最后一个是全局统计，并排显示导致用户理解为"480 条中筛出 3 条"。

**修复**：去掉统计行，让 `PaginationControls` 统一表达，或在 panel-header 显示全局信号。

---

### P1 — 应该修

#### P1-1：素材卡片不显示实体标签

**现象**：`DiscoveryItem` 有 `entity_ids`、`entity_names`（`types.ts:411-412`），但 `StreamCard`（`page.tsx:36-76`）完全不渲染。

**影响**：运营无法快速判断素材关联了哪些实体，无法判断是否已被聚类。

#### P1-2：素材与事件断裂

**现象**：看不到一条素材是否已被聚类到某个 `IntelEvent`。实时流和热点簇之间无双向导航。

**影响**：实时流是信息孤岛。运营看到感兴趣素材，无法直接跳到它所属事件。

#### P1-3：自动刷新无感知

**现象**：代码层面有 `useAdaptivePolling` 轮询 `loadStreamData`（`app.tsx` 运行时感知 tab 列表包含 stream），但页面没有任何视觉反馈——无加载指示器、无"最后更新时间"、无新条目动画。

**影响**："实时流"叫实时，但用户感知不到实时。

#### P1-4：平台/来源选项只从当前页推导

**现象**：`platformOptions`/`sourceOptions`（`page.tsx:93-101`）从当前页 `items` 提取。换页后选项会变化，之前选中的筛选条件可能突然消失。

**影响**：功能 bug。用户想筛某个来源，当前页没覆盖则看不到选项。

---

### P2 — 建议修

#### P2-1：卡片标题 14px 与摘要视觉差异不够

标题（14px strong）vs 摘要（默认大小）对比不足，快速滚动时无清晰视觉锚点。建议标题 15-16px。

#### P2-2：无用户状态管理

没有"已读/未读"、"收藏/忽略"机制。运营看过的重要素材无法标记，每次打开都是白板。

#### P2-3：过滤栏 4 行控制区占首屏 ~27%

过滤栏 + 排序行 + 统计行 + 分页 = ~188px，在 1080p 首屏占 27%。信息检索研究表明控制区应尽量精简。

#### P2-4：分页控件出现两次

`PaginationControls` 在列表上下各出现一次（`page.tsx:236-247` 和 `269-279`），信息冗余。

#### P2-5：状态指示器缺失

`item_state` 有三种值（`new_item`/`updated_item`/`seen_item`），以纯文本显示在 score-row 中，无颜色区分。对比 events 页面有 `status-badge` 组件用颜色编码。

#### P2-6：热度以纯数字显示

`engagement_score` 显示为"热度 42"，大量卡片中无法快速比较。建议分级可视化。

## 三、优化方向

### 方向 A：后端 API 加过滤参数（解决 P0，阻塞其他所有优化）

给 `GET /api/admin/intel/stream` 增加：`time_range`, `platform`, `source`, `item_state`, `min_engagement`, `max_engagement`, `q`（搜索）查询参数。

后端 `list_discovery_items` 数据在内存中，服务端过滤性能代价几乎为零。PostgreSQL 路径同样可直接加 WHERE 子句。

**涉及文件**：
- `backend/app/routes/intel.py`（路由参数）
- `backend/app/store_mixins/intel_mixin.py`（数据层过滤逻辑）
- `frontend/src/lib/api.ts`（前端 API 调用）
- `frontend/src/screens/stream/page.tsx`（过滤逻辑改造）
- `frontend/src/screens/stream/state.ts`（state hook 传参）

### 方向 B：卡片信息密度增强（解决 P1-1、P2-1、P2-5）

纯前端改动，数据字段已有：
- 渲染 `entity_names` 为标签
- 标题放大到 15-16px
- 摘要加两行截断（`-webkit-line-clamp: 2`）
- `item_state` 改用彩色圆点指示器（复用 `status-badge` 模式）

### 方向 C：控制区精简（解决 P2-3、P2-4、P0-2）

4 行 → 3 行：
- 第 1 行：搜索框 + 时间过滤 + 重置
- 第 2 行：快捷筛选 chips（来源/平台带数量）+ 排序 radio + 每页选择
- 底部：分页只出现一次
- 去掉误导统计行

### 方向 D：用户状态管理（解决 P2-2）

- 已读/未读：最轻量方案是 localStorage 存已读 ID 集合
- 忽略：前端标记 + 可选后端持久化
- 需和方向 A 的 API 过滤配合（后端支持 `is_read` 参数）

### 方向 E：实时刷新感知（解决 P1-3）

轮询已有，增加视觉反馈：
- 页面顶部显示"上次刷新于 X 秒前"
- 新数据进来时显示"有 N 条新素材"横幅，点击追加到列表

## 四、实施优先级

```
方向 A（后端 API 过滤）   ← 第一步，阻塞其他所有优化
  ↓
方向 B（卡片信息密度）    ← 第二步，纯前端，投入小价值高
  ↓
方向 C（控制区精简）      ← 第三步，配合方向 A 的过滤改造
  ↓
方向 D（用户状态管理）    ← 第四步，独立于其他方向
  ↓
方向 E（刷新感知）        ← 随时可以做
```
